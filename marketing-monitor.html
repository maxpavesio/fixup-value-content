Marketing Monitor

Daily AI watchdog account pubblicitari · Google Ads + Meta · zero touch

Cosa è: sistema autonomo che ogni mattina alle 08:23 controlla i conti pubblicitari attivi, calcola KPI vs settimana/mese/anno precedente, applica logica semaforo e invia un report email per gruppo cliente.

Stack: GitHub Actions cron · Python 3.12 · Google Ads API v20 · Meta Marketing API v23 · Gmail SMTP · YAML config self-service

Esecuzione: 100% cloud · indipendente da PC del PM · log auditabile su GitHub · email recapitate ai destinatari giusti per ogni cliente

Use case agenzia. 50 account adv monitorati ogni giorno su 4 gruppi cliente (ecommerce multi-country + lead-gen B2B). Le anomalie arrivano in inbox prima della prima riunione del mattino, non a fine settimana quando il danno è già fatto.
Tempo controllo manuale evitato
~12h/sett

50 account × 3min check + correlazione vs benchmark = 2,5h/giorno PM senior, sostituiti da run automatico

📊 Cosa monitora

Per ogni account vengono calcolati 11 KPI su 5 finestre temporali (settimana corrente, settimana precedente, MTD, mese precedente, anno precedente) e confrontati WoW / MoM / YoY.

Sistema semaforo

Ogni KPI ottiene uno stato verde, giallo o rosso in base a soglie configurate. Lo stato dell'account è calcolato sui core KPI (revenue/ROAS/leads per ecom; leads/CPL per lead-gen) — un singolo CPC drogato non rende l'account rosso.

🎯 Logica account-aware

Account ecommerce default · 45 acct

Core KPI: Fatturato, ROAS, Leads

Warning specifici: ROAS <1, drop CTR >50%, frequenza Meta >3.5, pacing budget

Esempi: Aurora Retail, Aurora Fashion (multi-country), Polaris Gadgets, Helios Commerce, Vega Wines, Sirius Beauty, Nova Foods

Account lead-gen flag dedicato · 5 acct

Core KPI: Leads, Cost per Lead

Comportamento: Fatturato e ROAS mascherati ("n/d" in tabella) · warning ROAS<1 soppresso (non avrebbe senso) · soglia lead_zero_min_spend attiva (alert se spesa >100€/sett senza un solo lead)

Esempi: Pulsar B2B, Quasar SaaS, Magnetar Finance, Centauri Legal

Senza questa distinzione, gli account lead-gen apparirebbero rossi ogni mattina (perché conversione = lead, non revenue). Falso allarme costante = email ignorata.

🔄 Manutenzione self-service

Tutta la configurazione vive in un unico file YAML versionato. Modifiche tramite GitHub web UI — zero terminale, zero deploy manuale.

Aggiungere un nuovo cliente

Edit config/accounts.yml → aggiungi blocco account sotto il gruppo giusto → commit. La run successiva (08:23) lo include automaticamente.

- name: Nuovo Brand
  slug: nuovo-brand
  platforms: [google, meta]
  google_customer_id: "XXX-XXX-XXXX"
  google_login_customer_id: "YYY-YYY-YYYY"   # MCC agenzia
  meta_account_id: "act_XXXXXXXXX"
  budget_monthly_eur:
    google: 3000
    meta: 2000
  extra_recipients:
    - account.manager@brand.example

Modificare destinatari

Aggiungi/rimuovi email sotto recipients: del gruppo (visibilità totale) o sotto extra_recipients: dell'account (visibilità scoped). Il bucketing si ricalcola al run successivo.

Cambiare tipo account o soglie

Setta account_type: lead_gen per disattivare warning revenue/ROAS. Per modificare soglie globali edita la sezione thresholds: in fondo al file.

Trigger manuale immediato

Tab Actions → workflow Daily Marketing Monitor → Run workflow → opzionale dry_run: true per testare senza inviare email.

🎁 Cosa porta a un cliente

  • Daily situational awareness · arrivi in ufficio sapendo già se ieri qualcosa è andato storto, non lo scopri venerdì pomeriggio
  • Distribuzione granulare · client lead riceve i suoi account, brand manager riceve il suo brand, founder riceve l'aggregato — senza che nessuno gestisca CC list manualmente
  • Threshold personalizzate · soglie tarate sul tipo di account (ecom vs lead-gen), non KPI generici
  • Indipendenza operativa · funziona se sei in vacanza, in volo, in malattia — il cron non si ammala
  • Storico auditabile · ogni report è committato in repo, recuperabile come time series per analisi trend
  • Estensibile · aggiungere TikTok Ads, LinkedIn Ads, Klaviyo o qualsiasi API è una skill in più dello stesso pattern
